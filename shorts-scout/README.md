# shorts-scout

Ежедневный сборщик готовых приколов для англоязычного канала YouTube Shorts.
Скрипт сам ходит по Reddit и YouTube, отбирает самые горячие короткие ролики
за сутки, убирает уже показанные и кладёт отчёт в `reports/ГГГГ-ММ-ДД.md`.
Вам остаётся выбрать из списка, а не искать.

## Что внутри

| Файл | Назначение |
|------|-----------|
| `scout.py` | сбор, ранжирование, отчёт, скачивание, конвертация в 9:16 |
| `publish.py` | заголовки, переработка видео, загрузка на YouTube по расписанию |
| `edit.py` | монтаж: хук, субтитры по речи, панчлайн, полоса прогресса, громкость |
| `fonts/` | шрифт подписей Montserrat ExtraBold (лицензия OFL) |
| `config.json` | сабреддиты, поисковые запросы YouTube, размер отчёта |
| `.env.example` | какие ключи нужны |
| `reports/` | ежедневные отчёты (md + json) |
| `state/seen.json` | что уже показывалось (создаётся автоматически) |
| `downloads/` | скачанные ролики (не попадают в git) |
| `ready/` | готовые Shorts и метаданные (не попадают в git) |

## Источники

| Источник | Что берёт | Ключ |
|----------|-----------|------|
| Reddit | топ видеопостов за сутки в 10 «смешных» сабреддитах | бесплатный, нужен |
| YouTube | самые просматриваемые свежие Shorts по запросам | бесплатный, нужен |
| Telegram | видео из публичных каналов (funnyvideos, funny_videos, fails) | не нужен |
| Dailymotion | трендовые ролики до 60 с из раздела Fun и поиск | не нужен |
| Coub | горячие лупы и теги funny / fail / animals | не нужен |
| Imgur | viral-галерея за сутки, только видео | бесплатный, нужен |
| Twitch | самые просматриваемые клипы за сутки (Just Chatting, Music) | бесплатный, нужен |
| Bluesky | посты с видео по запросам | не нужен, но с серверных IP бывает 403 |

Любой источник выключается в `config.json` полем `"enabled": false`.
Coub и Telegram часто дают контент без слов или на русском, отбирайте по превью.

Не вошли и почему: TikTok и Instagram без входа в аккаунт ничего не отдают,
9GAG закрыт Cloudflare, X (Twitter) API платный. Если захотите TikTok,
самый надёжный путь: yt-dlp с cookies вашего аккаунта по списку профилей.

## Ключи

1. **Reddit.** Откройте <https://www.reddit.com/prefs/apps>, создайте приложение
   типа *script*. Понадобятся `client id` (строка под названием приложения)
   и `secret`.
2. **YouTube Data API v3.** В <https://console.cloud.google.com/apis/credentials>
   создайте проект, включите *YouTube Data API v3*, создайте API key.
   Бесплатной квоты (10 000 единиц в день) хватает с запасом: скрипт тратит
   около 600 единиц за запуск.
3. **Imgur.** <https://api.imgur.com/oauth2/addclient>, тип
   *Anonymous usage without user authorization*. Нужен только Client ID.
4. **Twitch.** <https://dev.twitch.tv/console/apps>, *Register Your Application*,
   категория Other. Нужны Client ID и Client Secret.

Скопируйте `.env.example` в `.env` и заполните. Незаполненные источники
пропускаются, остальные работают.

## Запуск на своём компьютере

```bash
cd shorts-scout
pip install -r requirements.txt
set -a; source .env; set +a
python3 scout.py
```

Отчёт печатается в консоль и сохраняется в `reports/`.

Скачать кандидатов и сразу привести к вертикали 1080x1920 (нужен `ffmpeg`):

```bash
python3 scout.py --download --vertical
```

Файлы окажутся в `downloads/ГГГГ-ММ-ДД/`, вертикальные версии с суффиксом `_v`.
Если YouTube отвечает «Sign in to confirm you're not a bot», экспортируйте
cookies из браузера расширением *Get cookies.txt LOCALLY* и укажите путь
к файлу в `YTDLP_COOKIES`.

Полезные флаги:

* `--no-mark-seen` не запоминать показанные ролики (посмотреть ещё раз).
* `--only telegram,coub` запустить только часть источников.
* `--input-json файл` прогнать ранжирование на готовом списке (отладка).

## Публикация: `publish.py`

Берёт номера из отчёта и делает из них готовые Shorts:

1. скачивает ролик;
2. пишет английские заголовок, описание, теги, хук и панчлайн. Claude смотрит
   четыре кадра ролика и шутит про то, что на них происходит. Без ключа
   Anthropic используется шаблон, тексты можно задать и вручную (`--captions`);
3. перерабатывает видео (см. ниже);
4. загружает на YouTube с отложенной публикацией в ближайший свободный слот.

```bash
python3 publish.py reports/2026-10-29.json 1 4 7
```

Только подготовить файлы, ничего не загружая:

```bash
python3 publish.py reports/2026-10-29.json 1 4 7 --no-upload
```

Готовые видео и метаданные лежат в `ready/<дата>/`: `*_short.mp4` и `*_meta.json`.
Загруженные ролики записываются в `state/published.json` и повторно не грузятся,
занятые слоты тоже учитываются.

Флаги: `--now` публиковать сразу без расписания, `--no-claude` только шаблон,
`--no-subtitles` не распознавать речь, `--captions файл.json` свои тексты:

```json
{
  "1": {"title": "Girls vs Boys: water bottle edition", "hook": "Water bottles: girls vs boys",
        "punchline": "Boys just bring the whole jug", "subtitles": false}
}
```

Ключ это номер ролика в отчёте. Если заданы `title`, `hook` и `punchline`,
Claude не вызывается.

### Переработка видео

YouTube не пускает в монетизацию перезаливы без изменений, поэтому каждый
ролик проходит через `edit.py`:

* вертикаль 1080x1920, по бокам размытый и затемнённый кадр того же видео;
* хук сверху на всё время ролика;
* субтитры по речи (faster-whisper). Они появляются, только если речь
  распознана уверенно: на музыке и шуме их не будет;
* панчлайн крупно по центру в последние 2,5 секунды;
* подпись канала внизу, если задан `channel_handle` в `config.json`;
* жёлтая полоса прогресса внизу;
* громкость выровнена до -14 LUFS, битрейт ограничен, чтобы минута весила до 20 МБ.

Зеркалирования, ускорения и смены тона нет намеренно: они не делают ролик
авторским, а попытки обойти проверку YouTube наказывает строже.

При первом запуске faster-whisper скачивает модель распознавания, около 150 МБ.
Модель меняется полем `whisper_model` (`tiny` быстрее, `small` точнее).

Настройки в разделе `publish` файла `config.json`:

| Поле | Что значит |
|------|-----------|
| `timezone`, `slots` | часовой пояс и время публикаций, по умолчанию 12:00, 17:00, 21:00 по Нью-Йорку |
| `privacy` | статус при `--now`: `public`, `unlisted` или `private` |
| `category_id` | категория YouTube, `23` это Comedy |
| `default_tags` | теги, которые добавляются всегда |
| `channel_handle` | подпись канала внизу видео, например `@yourchannel` |
| `subtitles` | распознавать ли речь для субтитров |
| `whisper_model` | модель распознавания: `tiny`, `base`, `small` |
| `claude_model` | модель Claude для заголовков |

### Доступ к YouTube

1. В <https://console.cloud.google.com/> откройте тот же проект, где делали
   API key, и убедитесь, что *YouTube Data API v3* включён.
2. *APIs & Services → OAuth consent screen*: тип *External*, добавьте свой
   Google-аккаунт в *Test users*.
3. *Credentials → Create credentials → OAuth client ID*, тип *Desktop app*.
   Скачайте JSON и положите как `shorts-scout/client_secret.json`.
4. При первом запуске `publish.py` откроется браузер: войдите в аккаунт,
   к которому привязан канал. Токен сохранится в `state/youtube_token.json`.

**Важно про приватность.** YouTube оставляет приватными все ролики, загруженные
через API из непроверенного проекта Google Cloud. Отложенная публикация в таком
случае тоже не сработает. Есть два пути:

* пройти проверку YouTube API (форма аудита:
  <https://support.google.com/youtube/contact/yt_api_form>), после неё ролики
  публикуются по расписанию сами;
* до проверки загружать скриптом и раз в день открывать YouTube Studio,
  чтобы вручную переключить загруженное в «Открытый доступ» или назначить время.

Квота YouTube API: загрузка видео стоит намного дороже поиска, бесплатных
10 000 единиц в день хватает на несколько роликов. Точная цена операции
`videos.insert` указана в таблице квот Google:
<https://developers.google.com/youtube/v3/determine_quota_cost>.
Если квоты не хватит, скрипт остановится с ошибкой, а уже готовые файлы
останутся в `ready/`.

### Права на ролики

В описание каждого Shorts автоматически добавляются автор, ссылка на оригинал
и просьба написать, если автор против. Это не защищает от страйков полностью,
но снижает их число. Удаляйте ролик по первой жалобе: три страйка за 90 дней
закрывают канал.

## Автозапуск в GitHub Actions

Workflow `.github/workflows/shorts-scout.yml` запускается каждый день в 06:00 UTC,
собирает отчёт и коммитит его в репозиторий. Чтобы он заработал, добавьте
секреты в *Settings → Secrets and variables → Actions*:
`REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET`, `YOUTUBE_API_KEY`,
`IMGUR_CLIENT_ID`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`.
Без ключей отчёт всё равно соберётся из Telegram, Dailymotion и Coub.
Скачивание в Actions не делается: YouTube блокирует загрузку с серверных
адресов. Скачивайте на своём компьютере командой выше.

## Как считается `heat`

У каждого источника своя мера популярности: голоса (Reddit, Imgur), просмотры
в час (YouTube, Telegram, Dailymotion), лайки (Coub, Bluesky), просмотры клипа
(Twitch). Она делится на `reference` источника из `config.json` и даёт 0..100.
Ролики длиннее 60 с получают штраф (придётся резать), короче 15 с небольшой
штраф, уже вертикальные получают бонус. В отчёт попадает не больше
`max_per_source` роликов от одного источника.

Подкручивайте `reference`, если один источник всегда упирается в 100 или
наоборот никогда не поднимается.
